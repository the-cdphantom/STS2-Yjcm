# 孙乾宇宙灼烧联动（1.2.2）

贡献来源：[SSadamune 的 PR #1](https://github.com/the-cdphantom/STS2-Yjcm/pull/1)，审查快照 `a96d061bf028e71a5ac47b13a42c2084d33cb770`。按差异整合到当前工程，保留后续新增内容；源码整合不等于操作 GitHub 上的 PR 合并按钮。

## 效果

- 龙套演员使用一枕清梦时，给予、立即触发两次、回合结束恢复生命并移除的火攻均改为孙乾宇宙灼烧。伤害及熄灭判定委托对方 `TriggerBurning`，不复制其内部规则。
- 武诸葛/董卓两张朱雀羽扇继续共用装备球；持有者是龙套演员时，每次攻击施加2层灼烧，其他角色保持2层火攻。
- 玩法按卡牌/装备的实际持有者判断，不按本机角色判断；联机队友使用龙套演员不会把本人的结算改成灼烧。
- 1.2.2：演员持有的一枕清梦通过 `Tags` 只读派生孙乾公开 API 返回的 `BurningCardTag`，使火种按伙伴原生钩子加层并消耗。不修改规范实例/基础标签集合，不受另一玩家查看卡面的影响；普通角色和伙伴缺失时不附加灼烧标签。
- 火攻、董卓火攻、借东风、谋火计与一枕清梦使用 `HuoGongVar` 接入原生给予层数预览；一枕清梦在演员持有时解析伙伴已加载程序集 `Squ.Powers.BurningPower` 的规范实例进行预览。只改 `PreviewValue`，不给活实例、不修改 `BaseValue`，实际施加仍传基础值，避免重复计算火种和污染存档/联机状态。

## 接口与加载

当前核对孙乾宇宙 `main` 提交 `38ca437e49957a81be9ab6b9e952ea89ca347d0c`，`Api/SunqianUniversePublicApi.cs` blob `a0e0886b7195bc71a93aa3dcf354d377651cf98d`；使用其公开 `BurningCardTag`，保留的三参数 `TriggerBurning(PlayerChoiceContext, Creature, CardModel)` 与本项目兼容。旧 `feature/cross-mod-interop` 不包含这些新接口，联动需使用含新接口的孙乾版本。

反向代理17个方法，无伙伴硬引用或清单强依赖；不安装伙伴时安全退回原效果。Loader选择游戏版本后只调用内容的统一幂等初始化入口，不再独立挂载Harmony/设置/遥测。两版均逐类挂载补丁，单个可选目标失败仍不阻断其他补丁。

## 验证边界

`tools/build.ps1 -Variant all` 覆盖程序集/幂等声明、17个代理签名、卡牌/装备接入及本地化；.NET9辅助测试验证32种互斥提示决策、缺失伙伴安全值、真实辅助方法向模拟伙伴API转发参数，以及Loader16次并发调用只初始化一次。MainFile静态日志依赖Godot，不能在独立.NET进程实际启动其完整注册流程。

`FirePreviewCases` 运行实际卡牌变量，覆盖基础/升级、正负加成、普通/演员持有、伙伴缺失、目标传入、重复预览不叠加、退出预览还原及规范实例保护。全局给予钩子与伙伴边界被模拟，不等于实际加载孙乾 DLL 的战斗测试。

这些不是实际双Mod游戏/联机/回放验证；最终仍需双方进游戏验证伙伴代理绑定、灼烧熄灭与UI交互。
